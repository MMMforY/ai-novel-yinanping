## 原项目与资源

部署前后核对，已有容器的 ID、启动时间、重启次数、健康状态、端口和资源限制相同；已有 systemd 服务的 PID、启动时间、重启次数和运行状态相同。防火墙、SSH、Docker 配置文件的 SHA-256 相同。详细记录留在本地 `.local/deployment/`，不上传其他项目的配置或标识。

验收采样时 FastAPI 约 37.37MiB，Caddy 约 10.57MiB，合计约 48MiB；服务器仍约有 2.4GiB 可用内存。配置限制为 512MiB + 128MiB、0.5 + 0.25 CPU，不加载本地大模型。资源数值是演示请求下的瞬时读数，真实请求时需继续观察。

两个新增服务均以用户 10001 运行，根文件系统只读，移除全部 Linux capabilities，禁止提权。Caddy 的镜像移除了不需要的低端口文件 capability，保持上述限制下可正常执行。

## 当前限制

- 初期入口通过 SSH 隧道，未开放公网服务或配置域名、HTTPS。
- 未配置真实模型，因此尚未验证真实生成质量、长上下文耗时与供应商流量费用。
- 手机验证使用 Chromium 手机视口；真实手机的系统长按选区尚未实机验证。
- localhost:5173、localhost:18787 与 127.0.0.1:18787 是不同浏览器来源，各自拥有独立书库；没有自动迁移或云同步。
- 单 worker、全服务并发 2、每分钟最多 60 次生成，适合当前小规模体验。
